# 02 方案：调用流程、动态决策与技术取舍

## 总体结构

```text
请求 JSON ──► request.py 校验/规范化（时间统一成 YYYY-MM-DD HH:MM；幂等键 = 规范化后请求内容的哈希）
                │
                ▼
          agent.py ReAct 循环 ◄──────────── llm.py：OpenAI 兼容（DeepSeek）/ Claude / Mock
          │  模型选择工具 + 参数 + 一句话依据(reason)
          ▼
          tools.py 执行工具，结果写入事实账本（RunContext.facts）
          │  结果（JSON）交回模型 → 模型决定下一步或结束
          ▼
          save_draft：按账本复核 → stores.py 幂等写草稿（或注入失败）
                │
                ▼
          build_report：状态、草稿结果、pending_confirmations 取自账本（pending_items 是模型写的文字，不校验）；
                        保存后用最终账本重新复核，复核不通过则判定草稿过期；
                        模型总结只作参考，只检查“已发布/已保存”两类声称
```

## 一次运行的调用流程

1. 模型拿到请求（素材、渠道、时间、是否硬性、当前时间 `as_of`；或 `scope=pending`）和 8 个工具的说明。
2. `scope=pending` 时，模型先调用 `list_pending_materials`，返回的待审素材（连同负责人登记的发布要求）加入本次待处理清单。
3. 对每个素材，模型通常按 `get_material → check_rules →（verify 时）verify_copyright → query_slots` 收集事实，再按结果选择动作；
   可以在一轮里并行调用多个工具，有依赖的调用分轮发出。
4. 全部处理完后调用一次 `save_draft` 提交所有条目。复核不通过返回 `problems`，模型修正后重提；存储失败返回 `retryable`，模型决定是否重试。
5. 模型不再调用工具时循环结束，程序生成报告。

## 工具

| 工具 | 作用 | 典型返回 |
|---|---|---|
| `list_pending_materials` | 找出待审核素材；`scope=pending` 时把它们加入待处理清单 | 待审核列表及各自登记的发布要求 |
| `get_material` | 读素材元数据 | 是否存在、缺失必填字段、发布要求问题（缺失/渠道未配置/已过期）、是否已在排期 |
| `check_rules` | 规则检查 | 命中项及级别 block / warn / verify |
| `verify_copyright` | **补查**版权登记库 | valid / expired / not_found（按发布日期判断） |
| `query_slots` | 查时段 | 是否可用、冲突原因、更近时段为什么不可用、最多 3 个替代时段 |
| `request_confirmation` | **请求确认**：登记待确认事项，可为该素材在本次请求内暂留一个替代时段 | 确认单号，状态 awaiting_user |
| `block_material` | **阻断**（同时作废该素材未完成的确认） | 阻断记录 |
| `save_draft` | 复核并保存草稿（唯一写操作） | created / updated（含 changes）/ duplicate_unchanged，或失败原因 |

每个工具都要求模型填写 `reason`（一句话依据），它进入运行记录的“决策依据”列；不要求、也不记录模型的内部思考过程
（DeepSeek 思考模式返回的 `reasoning_content` 只按接口要求回传给模型，不写入运行记录）。

## 动态决策：模型决定什么

| 工具结果 | 模型可选动作 |
|---|---|
| 素材不存在 / 必填缺失 / 发布要求缺失或无效 | 标记 needs_info，写清需补充什么，不再查规则时段 |
| 已在已有排期中 | 标记 duplicate |
| block 级命中 | `block_material` |
| verify 级命中 | `verify_copyright` 补查 → valid 继续；expired 阻断；not_found 视为信息缺失 |
| warn 级命中 | `request_confirmation` 说明风险，让用户决定 |
| 期望时间被占用 | 在替代时段里选一个，`request_confirmation` 登记并暂留，草稿标记待确认 |
| 硬性时间被占用 | 不改时间；`request_confirmation` 提出“协调占用方 / 改到某时段”让用户选，或 `block_material` |
| 草稿复核不通过 | 按 `problems` 修正后重提 |
| 保存失败 `retryable=true` / `false` | 重试一次 / 停止并报告失败 |

真实模型运行记录里能看到同一工具返回不同结果时动作不同：`verify_copyright` 返回 valid（M07）→ 继续查时段排期，返回 expired（M05）→ 阻断；
`save_draft` 返回 `retryable=true` → 重试成功，`retryable=false` → 停止并如实报告失败；`query_slots` 可用 → 直接排期，不可用 → 选替代时段并请求确认。

## 工具层护栏：程序保证什么

提示词写明边界，但关键边界不依赖模型自觉，由工具层兜底：

1. **没有发布工具**；报告里 `published` 恒为 false。模型最终答复出现“已发布/已上线/发布成功”等陈述（排除“请勿视为已上线”“是否已发布：否”“确认后才会发布”这类否定、疑问、条件句）会记入 `guard_flags`。
2. **保存结果不靠模型说**：`draft` 只取 `save_draft` 的真实返回，以**最后一次成功写入**为准；同一次运行内，之后的修订失败会单独标出，不会把本次已写入的草稿说成“未保存”（报告不读取以往运行的草稿：后一次运行保存失败时显示 `saved=false`，库里已有的旧草稿不受影响，也不会在报告中提示）；模型声称已保存但实际没有任何成功写入时告警。
3. **硬性时间不得擅改**：`fixed` 素材的建议时段只能等于要求时间或留空，替代方案只能出现在待确认事项里。
4. **改期必须先确认**：期望时间改为别的时段时，必须有一条**仍在等待用户**的确认，其 `proposed_slot` 等于该时段；同一素材再次提议会替换上一次（旧提议作废并释放暂留），阻断会作废该素材的全部待确认。
5. **结论必须与事实一致**：没读素材不能下结论；信息缺失时不能进入排期，也不能用“阻断”代替（同时有 block 命中时 needs_info、blocked 都能通过）；block 命中或版权失效的素材不能进入排期，若同时信息缺失或已在排期，可标记 needs_info / duplicate；
   warn 命中不能直接 schedule；verify 未补查不能排期；保存时还会按版权登记库核对：有记录但不覆盖发布日期的授权会被拒绝，登记库查无记录时不拦截，除非模型调用过 verify_copyright（not_found 按信息缺失处理）。
6. **无冲突**：
   - 保存时**重新读取并规范化已有排期**复核（防止查询后排期被改、或手改写成 `2026-11-3 19:00` 被漏判），并检查本次草稿内部有无撞车；
   - 同一请求里多个素材要求同一时段时，**硬性要求优先，其次按请求顺序**；已确定不能排期（阻断/缺信息/重复）的素材，以及期望时间已提议改到别处的素材，不再占用自己的要求时段（硬性素材提了替代方案也继续占用）；
   - `query_slots` 的替代时段已排除已有排期、其他素材仍要求的时段、已暂留给其他素材的时段、早于 `as_of` 的时段。
7. **防重复**：幂等键只由规范化后的请求内容决定（不含 request_id、as_of、故障开关）。草稿方案签名只看结构化字段和工具事实（结论、时段、确认状态、
   暂留时段、规则命中、版权核验、缺失项），**不看模型措辞**：同签名 → `duplicate_unchanged`（保留原草稿；此时报告的 `draft_status` 仍显示“已写入草稿”，报告里的风险说明是本次措辞，草稿库保留第一次保存的文字）；签名变化（如已有排期被改后重提、新发现风险）→
   原草稿 `version+1`，返回 `changes` 并保存旧版本摘要，不新建。请求内完全相同的条目在入口合并；同一素材给出不同要求则拒绝并要求先明确。
8. **过期检测**：生成报告时用最终账本重新执行 save_draft 的复核。会让复核不通过的变化判为过期，状态为 `incomplete` 并给出 `draft.stale`：待排期条目被阻断、建议时段被占用、直接排期的素材新增待确认、建议时段对应的提议被替换。不改变复核结论的变化不会被判过期：已待确认的素材再加一条确认、建议时段留空的条目（如硬性冲突）换了提议、needs_info / duplicate 条目被阻断、被占时段释放。
9. **失败不留脏数据**：故障注入发生在写入前；真实写入用临时文件 + `os.replace` 原子替换；草稿库文件损坏、任何存储异常都作为 `save_failed` 如实返回。
10. **上限**：默认模型轮数 40、工具调用 80（CLI 可调），到达上限返回 `incomplete` 及原因；同一轮里超限未执行的调用也写入 trace。

## 技术取舍

| 选择 | 原因 | 代价 |
|---|---|---|
| 原生实现 ReAct 循环，不用 LangGraph / ADK 等框架 | 循环本身不到 100 行；护栏、账本、报告需要完全可控，便于解释和测试 | 没有现成的可视化、断点续跑 |
| 核心零第三方依赖（标准库 + unittest） | 评审在隔离环境可直接运行测试和 Mock | 模型 SDK 需另装 |
| 官方 SDK 接模型，延迟导入 | 少写 HTTP 细节（重试、超时、错误类型）；未安装也不影响离线运行 | 依赖 SDK 版本，见 requirements.txt |
| 同时支持 OpenAI 兼容接口与 Claude | 国内可直连 DeepSeek / 通义；也可用 Claude | 两套消息格式，各有一组适配测试 |
| 护栏放在工具层而不是只写进提示词 | 越权发布、虚报保存是关键缺陷，不能靠模型自觉 | 复核较严时模型可能要多改一轮（最终 28 次真实运行中，v4-pro 有 1 次被拒后自行修正，其余没有被复核拒绝） |
| 报告由账本生成，模型总结只作参考 | 防止模型“说的”和“做的”不一致 | 模型写的风险说明不做语义校验（工具事实另存 `risk_facts`） |
| 待确认项写入草稿，不做交互式确认 | 题目交付的是“可确认的排期”；交互确认会让验证不可复现 | 用户确认后需重新提交请求 |
| `as_of` 写进请求 | 判断“时间已过期”需要当前时间；样例固定它，任何时候运行结果一致 | 不填时用系统时间 |
| Mock 用固定规则模拟模型 | 无 Key 时也能跑通全链路，验证幂等、保存失败和上限；越界类护栏（复核拒绝、声称检测、过期检测）由同样不需要 Key 的单元测试和脚本化假模型验证 | Mock 是条件分支，不证明真实模型效果（已在输出中标注） |

## 模型配置

- OpenAI 兼容：官方 `openai` SDK，默认 DeepSeek `deepseek-v4-pro`（也测了 `deepseek-flash`），`temperature=0`，`tool_choice=auto`；
  `function.arguments` 是 JSON 字符串，解析失败作为工具错误交回模型；`finish_reason` 为 length / content_filter 等中断情况、返回非 JSON 时报 `status=error`。
- Claude：官方 `anthropic` SDK，默认 `claude-opus-5-5`，`output_config.effort=medium`；每轮把模型返回的 content（含 thinking 块）原样追加回历史；
  `stop_reason=refusal` / `max_tokens` 视为调用失败；默认开启服务端拒答回退（`fallbacks="default"`，beta），代理不支持时 `ANTHROPIC_FALLBACKS=off`；没有任何凭据时启动即报错（退出码 2）。
- 两者的 SDK 自带重试（429/5xx/网络错误）；重试后仍失败，本次运行返回 `status=error`。
